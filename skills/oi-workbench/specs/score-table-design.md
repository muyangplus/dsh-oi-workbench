# 测试点与分数表设计规范（OI 向）

OI（OI、OI）**按测试点给分**。本规范说明如何设计 10-25 个等分/不等分测试点、
用**测试点编号区间表格**灵活分档、用**特殊性质**简化题目。

## 1. 评分方式（事实）

- 一道题通常 **10-25 个测试点**，每个测试点 4-10 分，总分 100。
- **等分**最常见：25 点 × 4 分、20 点 × 5 分；也可以按档不等分。
- 选手得分 = 通过的测试点数 × 每点分值（综合测试）。
- 部分 OJ 支持 subtask 捆绑评测，默认不用；赛事方要求时才用。

## 2. 分档：测试点编号区间表格（OI 题面通用格式，参考 `reference/` 自出参考题）

**不要**生硬套"20%/50%/100%"三档。通用做法是直接列出每档测试点编号、约束与特殊性质：

| 测试点 | $n\le$ | $m$ | 特殊性质 |
|---|---|---|---|
| $1,2$ | $10$ | $\le n$ | 无 |
| $3\sim 5$ | $18$ | $\le n$ | 无 |
| $6\sim 8$ | $10^2$ | $\le n$ | A |
| $9\sim 11$ | $10^2$ | $\le n$ | 无 |
| $12\sim 14$ | $500$ | $=1$ | 无 |
| $15$ | $500$ | $=n$ | 无 |
| $16,17$ | $500$ | $\le n$ | A |
| $18\sim 21$ | $500$ | $\le n$ | B |
| $22\sim 25$ | $500$ | $\le n$ | 无 |

特殊性质 A：……；特殊性质 B：……。

分档设计要点：

- **档位自由**：3-8 档都常见；每档 2-6 个测试点；档位可以只约束一个变量
  （如 $m=1$、$m=n$），不必三档齐全。
- **档位累计或并列皆可**：如 $n\le 18$ 档包含 $n\le 10$ 的约束（累计）；
  $m=1$ 档与 $m=n$ 档是并列特例。
- **"无特殊性质"档要写**：规范明确标注"无"。
- 表格放"数据范围"小节；每个变量的总体保证写在表前（如"对于所有测试数据：
  $1\le m\le n\le 500$，$s_i\in\{0,1\}$，$0\le c_i\le n$"）。
- 特殊性质定义写在表后。
- 时间/空间限制单独列出。

## 3. 特殊性质设计（简化题目的标准手段）

| 类型 | 例子 | 效果 |
|---|---|---|
| 数据取值受限 | $a_i\in\{0,1\}$、$a_i$ 互不相同 | 简化计数/比较 |
| 结构特化 | 树、链、二分图、DAG | 简化图论问题 |
| 输入受限 | $T=1$、$m=1$、$m=n$、$q=0$ | 简化多测/边界 |
| 参数特化 | $k\le 10$、$\sum s_i\le 18$ | 使枚举/状压可行 |

原则：
- 每个特殊性质必须能被生成器**精确制造**；
- 特殊性质是"简化"，不能是"换知识点"；
- 多个性质可叠加（A/B/C），表格中逐列注明。

## 4. 完整样例（不进题面，文件引用）

- 样例 1-2 放题面内（小规模，覆盖不同分支）。
- **完整样例 zip 平铺**：`additional_file/<英文题名>_samples.zip` 内含
  `1.in/1.out`、`2.in/2.out`、`3.in/3.out`（样例 3 为大样例；
  无大/小样例子目录、无 readme）。
- OJ 题面引用（Hydro）：
  `（见题目附件 [xxx_samples.zip](file://xxx_samples.zip)，其中样例 3 满足测试点 6, 7, 8 的约束。）`
- PDF 题面引用（官方格式）：
  `见选手目录下的 xxx/xxx3.in 与 xxx/xxx3.ans。该样例满足测试点 6, 7, 8 的约束条件。`
- 大样例数据由生成器产出（满足对应档约束），答案由 std 生成。

## 5. OJ 打包映射

### Hydro

- **逐点等分/不等分**（默认）：`testdata/config.yaml` 顶层 `cases`（每个 case 一个测试点）。
- **大样例/附加文件**：打包到 zip 的 `additional_file/` 目录（Hydro 导入为附加文件，
  不进评测数据），题面用 `file://` 引用。
- 捆绑评测才用 `subtasks`（`templates/problem.yaml` 模板 B）。

### HOJ（HimitZH/HOJ）

- 用 `generator/build_hoj_package.py` 生成 `problem_<pid>.json + problem_<pid>/测试数据` 的
  HOJ 导入 zip。
- 普通 OI 综合测试：`judgeMode=default`、`judgeCaseMode=default`，每个 `samples` 元素带
  `score`，分值加和 = 100。
- 子任务（最低分/平均分）：`judgeCaseMode=subtask_lowest` / `subtask_average`，同组用例
  设置相同 `groupNum`（从 1 开始）。
- 特殊/交互：`judgeMode=spj` / `interactive`，`spjCode` / `spjLanguage` 及额外文件按
  `docs/use/import-problem.md` 填写。
- HOJ 不支持 `file://` 附件下载：大样例请作为 `userExtraFile` 或另行放入服务器附加资源；
  题面中可保留下载说明，但导入后需在 HOJ 后台核对。

## 6. 自检清单

- [ ] 测试点 10-25 个，总分 100（等分或不等分说明清楚）
- [ ] 分档用测试点编号区间表格，档位自由（非固定三档），无特殊性质档显式标注
- [ ] 总体保证（所有测试数据）单独列出，覆盖每个变量
- [ ] 特殊性质有定义、有专属测试点、生成器可精确制造
- [ ] 大样例以附加文件 zip 提供，题面中引用（不内联）
- [ ] 题面表格 / 生成器 / 评测配置三方一致
- [ ] 复杂度错解在超档测试点 TLE，实测验证（见 data-design.md）
