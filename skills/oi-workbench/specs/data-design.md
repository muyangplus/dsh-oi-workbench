# 针对性数据构造规范（OI 向）

数据是 OI 题的灵魂。ACM 向数据只关心"判对错"；OI 数据还必须**按测试点分档**（数据范围分档 + 特殊性质，见 `score-table-design.md`）、**定向击杀每个档位之上复杂度的典型错解**、**卡住复杂度**、**覆盖边界**。

## 1. 数据点构成（每个测试点分档内部）

| 类别 | 占比（经验） | 作用 |
|---|---|---|
| 边界/极端 | 20-30% | 最小值、最大值、单元素、空串、全同、无解、负值、溢出边界（INT_MAX/LLONG_MAX） |
| 极限规模 | 30-40% | 逼近该档约束上界，卡复杂度 |
| 定向击杀 | 30-40% | 针对该档位以上复杂度的典型错解构造（见第 2 节） |
| 纯随机 | ≤10% | 仅作补充，永远不是主体 |

## 2. 错解枚举与击杀矩阵（三层错解模型）

写数据前，先按三层枚举**该档位选手最可能写出的错解**：

1. **思路层**：错误贪心、错误的状态转移、漏情况（如忘取模、未考虑负值、图不连通）。
2. **复杂度层**：复杂度更高的实现（O(n²) 当 O(n log n) 用）→ 用极限数据卡 TLE。
3. **实现层**：int 溢出、数组越界、边界写错（`<` 写成 `<=`）、未排序、多测未清空、死循环边界。

然后建立**击杀矩阵**：

| 错解 | 类型 | 击杀数据点 | 预期结果 |
|---|---|---|---|
| wrong1.cpp 错误贪心 | 思路 | kill-greedy1.in | WA |
| wrong2.cpp O(n²) 暴力 | 复杂度 | big-n.in | TLE |
| wrong3.cpp int 溢出 | 实现 | overflow.in | WA |

硬性要求：
- 每个 **思路层/实现层错解必须被至少一个数据点 WA 击杀**（不能靠 TLE 冒充）。
- 每个 **复杂度层错解必须被极限数据 TLE**（数据上界要够大）。
- 错解被杀时**不能连带 RE/FAIL**（如数组越界崩溃），RE 击杀不算数（OI 评测机对 RE 很敏感，且 RE 会让选手怀疑数据问题）。
- 用 stress 对拍验证：暴力 vs 正解在小数据上全对；错解 vs 正解在小数据上就能找到反例的，把反例**固化为正式数据**。

## 3. 卡复杂度的数据设计

- 时间复杂度上界 = 正解复杂度 ×（数据规模因子）。例：正解 O(n log n)，n ≤ 2×10⁵；O(n²) 实现 4×10¹⁰ 必 TLE。
- **卡常数**（OI 特色）：同一复杂度的不同实现常数差 2-5 倍。数据规模取"正解压线可过、高常数实现必 TLE"的区间，并在本机用 std 实测：`std 最坏数据运行时间 ≤ TL/3`。
- 最坏数据形态必须被构造出来：如"最坏情况下图是稠密的""树退化成链""所有查询都落在最大区间"。
- 多测数据：T 个测试的总规模上界（如 Σn ≤ 2×10⁵）要在题面写明、Validator 校验（累计上限纪律：题面声明、Validator 实际校验、生成器约束三方一致）。

## 4. 数据生成器纪律

- 每个测试点分档有独立生成器参数（`gen_tier1.py` / `gen_tier2.py`，或 C++ 生成器 + 参数）。
- 生成器**确定性**：固定 seed 可复现（OI 官方惯例：数据由生成器 + seed 决定，答案由 std 生成）。
- 生成器写完后**先过 Validator**（格式/范围校验），再生成答案（std 输出）。
- 样例必须来自生成器（或手写但明确标注），禁止"样例与正式数据格式不一致"。
- 对拍：`stress` 小数据随机对拍 ≥ 1 万轮（正解 vs 暴力），发现反例 → 固化 → 修 → 重跑。

## 5. 边界数据清单（每道题必查）

- [ ] n=1、n=max、m=0/全无操作、T=1、T=max
- [ ] 数值边界：0、负数、±(2³¹-1)、±(2⁶³-1)、取模边界（x=MOD-1）
- [ ] 字符串：空串、单字符、全同字符、最长串
- [ ] 图：单点、链、星形、完全图、不连通、重边、自环、环上链
- [ ] 树：链、菊花、完全二叉树、随机树
- [ ] 特殊性质档的"性质边界"（如 01 序列全 0/全 1/交替）
- [ ] 多测：单组最大 + 多组分摊最大

## 6. 数据量参考

- OI 正式数据：单题通常 20-25 个测试点（按数据范围分档，每档 5-13 个点，见 `score-table-design.md`）。
- 每个测试点档至少 4 个数据点（太少区分度不稳）。
- 样例 2-3 组，必须覆盖不同操作/不同输出类型（见 statement-style.md）。

## 7. 交付自检

- [ ] 每个测试点档数据点数量 ≥4，含边界+极限+定向
- [ ] 击杀矩阵填满：思路层/实现层错解全部 WA 击杀，复杂度层错解全部 TLE
- [ ] std 全 AC，暴力全 AC（小数据域），错解在矩阵预期位置被杀
- [ ] 所有数据过 Validator
- [ ] 固定 seed 全量可复现
- [ ] 生成器与数据一起交付（OI 官方要求数据可复现）
- [ ] 对拍/生成器随机数据严格满足题面全部约束（防越界 UB 假分歧，见 §8.1）
- [ ] 实现层错解保证终止且不 RE（int 溢出错解用 long long 控制二分范围，见 §8.2）
## 8. Windows 实测经验与踩坑记录（2025-07 二分+贪心出题实录）

以下条目来自一次完整的二分答案（提高组 档）出题闭环，每一条都对应一个真实踩坑与修复。

### 8.1 对拍/随机数据必须严格满足题面约束（防越界 UB 假分歧）

- **踩坑**：对拍随机数据生成颜色 c_i ∈ [1,5] 而 n=3（违反题面 c_i ≤ n），
  std 的 last[c[i]] 数组（大小 n+1）越界 → UB → std 与 brute 输出"分歧"。
  同一算法用 JS Map 实现（不越界）0 分歧，才定位为数据生成问题而非代码问题。
- **纪律**：随机范围必须以题面声明的约束为界（c_i ∈ [1, n]、a_i ∈ [1, 上限]…）；
  发现分歧先检查数据合规性，再怀疑算法。C++ 侧越界是 UB，可能只在部分数据上显现。

### 8.2 实现层错解必须被 WA 击杀，TLE/RE 不算击杀

- **踩坑**：wrong_int 全部用 int（含二分 lo/hi/mid），大和点 sum 溢出为负数后
  lo = mid + 1 每次只增 1 → 数十亿轮死循环 → TLE（违规：实现层错解不能靠 TLE 杀）。
- **修复**：二分范围 lo/hi/mid 用 long long（保证收敛），只让段重累加 cur 用 int
  溢出 → 判定错误 → WA。
- **纪律**：设计溢出错解时保证程序必然终止且不崩溃（RE/段错误不算击杀）；
  int 溢出只允许发生在"计算路径"，不允许发生在"循环控制路径"。

### 8.3 卡复杂度要构造最坏形态，随机数据会漏杀

- **踩坑**：wrong_slow（O(n²) 判定，每步线性查重）在随机数据上段长短
  （段重约束紧或颜色周期小）→ 实测 112ms 全 AC，只有"长段"形态才 TLE。
- **构造**：n=2×10^5 + 颜色周期 ≈ n/2（或颜色两两不同）+ 重量小（段重不截断段长）
  → 单次 check 即 O(n·周期) = 2×10^10 → 必 TLE。
- **纪律**：对复杂度层错解先跑随机数据实测计时；若不过 TL，构造"最坏段长/最坏形态"
  定向数据（长链、大周期、全异、稠密、无解边界）并固化进正式数据。

### 8.4 Windows 实操

- **Python 生成器编码**：print 中文注释或特殊字符（如 ²）在 GBK 控制台抛
  UnicodeEncodeError（文件已写完但脚本中断，后续点丢失）。文件头部加：
  ```python
  if hasattr(sys.stdout, "reconfigure"):
      sys.stdout.reconfigure(encoding="utf-8", errors="replace")
  ```
  注释里避免非 ASCII 数学符号（写 O(n^2) 而非 O(n²)）。
- **对拍效率**：Windows 进程启动 30-100ms/次，逐轮 spawn 1 万轮必超时。改为
  一次生成 N 个输入文件后批量跑：
  ```
  cmd /c "for /L %i in (1,1,N) do ( std.exe < t%i.in > s%i.out & brute.exe < t%i.in > b%i.out )"
  ```
  或同一语言内实现双算法对拍（JS/Python 各写贪心与暴力），C++ 侧只做小样本确认。
- **重定向**：PowerShell 不支持 `<` 输入重定向，用 `cmd /c` 包一层。
- **残留进程**：超时杀进程可能残留并锁定 exe（重新编译报 Permission denied），
  先 `Stop-Process` 残留的评测进程再编译。

### 8.5 参考击杀矩阵（本次实录，TL=1s，Windows g++ 14.2 `-O2 -std=c++14 -static`）

| 程序 | 类型 | 预期 | 实测 |
|---|---|---|---|
| std.cpp | 正解 | 25/25 AC | 25/25 AC，最坏 130ms ≤ TL/3 |
| wrong_mode（最小段数=众数，忽略段重） | 思路层 | WA | WA 18 点 |
| wrong_ub（二分上界=max a） | 思路层 | WA | WA 18 点 |
| wrong_slow（O(n²) 判定） | 复杂度层 | 小档 AC，大档 TLE | 1~5 AC；长段点单 check >8s |
| wrong_int（段重 int 溢出） | 实现层 | WA | WA 10 点（答案/中间段重 > 2^31） |

补充：`k 紧`（段数限制接近仅颜色约束的最小段数）是思路层错解（忽略段重/上界取 max）
的高发击杀形态，分档时应专门构造若干"答案 > max a_i"的点。
