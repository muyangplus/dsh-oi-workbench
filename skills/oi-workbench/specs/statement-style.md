# OI / OI 题面规范

OI 题面风格：结构固定、措辞严谨、**零做法提示**、数据范围用测试点表格、
大样例以附件形式提供。格式参考本仓库自出原创题：
- `reference/entry/`（入门级风格 4 题）
- `reference/intermediate/`（提高级风格 4 题）

## 1. 结构（固定顺序）

```markdown
# 题目名称

## 题目描述
（背景 1-2 句；直接定义问题）

## 输入格式
（第一行……接下来……；数据范围在变量首次出现处用中文括号标注）

## 输出格式

## 样例输入 1 / 样例输出 1
## 样例解释 1
（可选；不泄露关键结论/核心做法；紧跟样例 1 输出）

## 样例输入 2 / 样例输出 2
（大样例不内联，见第 5 节）

## 样例 3
（大样例文件引用）

## 数据范围
（总体保证 → 测试点编号区间表格 → 特殊性质定义）
（时间限制/空间限制）
```

## 2. 铁律：零做法提示

- 题面不得出现任何知识点/算法/复杂度提示：禁止"可用 DP""建议用堆""请用 64 位整数"等。
- 样例解释不得泄露核心做法。
- 数据范围声明（如 $a_i\le 10^9$）是数据定义，不算提示。
- 需要复杂背景故事/无效信息包装时见 `specs/story-statement.md`；【说明与澄清】只解释
  概念（子序列、连续子段、路径含端点、是否允许重复等），**禁止**提示性内容：
  答案量级/上限、64 位整数、答案至少为 1、只要求输出人数、并列取最小编号等。

## 3. 措辞规则

- 变量首次出现处标范围，用中文括号：`输入一个整数 $n$（$1\le n\le 500$）。`
- 输入/输出格式写全，无歧义；OJ 题明确 stdin/stdout。
- 术语前后一致；区间开闭、排序规则、"保证有解/可能无解"明确写出。
- 数学公式用 LaTeX（$...$）。

## 4. 数据范围（总体保证 + 测试点表格）

```markdown
## 数据范围

对于所有测试数据，保证：
- $1\le m\le n\le 500$；
- 对于任意 $1\le i\le n$，$s_i\in\{0,1\}$；
- 对于任意 $1\le i\le n$，$0\le c_i\le n$。

| 测试点 | $n\le$ | $m$ | 特殊性质 |
|---|---|---|---|
| $1,2$ | $10$ | $\le n$ | 无 |
| $3\sim 5$ | $18$ | $\le n$ | 无 |
| $6\sim 8$ | $10^2$ | $\le n$ | A |
| $12\sim 14$ | $500$ | $=1$ | 无 |
| $15$ | $500$ | $=n$ | 无 |
| $22\sim 25$ | $500$ | $\le n$ | 无 |

特殊性质 A：对于任意 $1\le i\le n$，$s_i=1$。

时间限制：1s；空间限制：512MB。
编译选项（C++）：`-O2 -std=c++14 -static`。
```

- 表格按需自由分档（见 `specs/score-table-design.md`），不套固定百分比。
- 表格必须覆盖输入中每个量的前提（下界、字符集、互异性、连通性、是否有解）。

### 4.1 评测环境与编译选项

全国统一评测时限以目标评测机为准，本机 Windows 计时仅作参考。

比赛封面/配置文件中固定写：

```text
编译选项：-O2 -std=c++14 -static
```

同时遵守以下注意事项：

- 程序名和输入输出文件名必须使用英文小写；
- `main` 返回值类型必须为 `int`，正常结束返回 `0`；
- 结果比较为全文比较（过滤行末空格及文末换行）；
- 提交源程序文件大小不得超过 100 KiB；
- 栈空间限制与题目内存限制一致；
- 禁止源码中修改编译器参数（如 `#pragma`）或使用系统结构相关指令；
- 只提供 Linux 格式附加样例文件。

### 4.2 IO 模式与评测模式（批次 2，v0.1.2）

- 每道题的 IO 与评测模式由 `spec.json` 控制（字段见 `templates/problem.yaml`）：
  - `io.type`：`standard`（stdin/stdout，默认）或 `file`（运行时读/写 `io.input`/`io.output`，文件名一律英文小写）；
  - `judge.mode`：`traditional`（逐点）/ `subtask`（捆绑，配 `subtasks`）/ `acm`（逐点即时，无部分分）；
  - `judge.spj` + `judge.checker`/`judge.interactor`：特殊评测，checker/interactor 源码放 `data/` 或 `checker/`
    （本地评测按 testlib 命令行约定：exit 0 = AC）。
- 题面「输入格式 / 输出格式」仅在文件读写时说明文件名，其余按本规范固定结构。

## 5. 样例与大样例（附件机制）

- 样例 1-2 内联在题面（小规模，覆盖不同分支/输出类型）。
- **完整样例 zip 平铺**：`additional_file/<英文题名>_samples.zip` 内含
  `1.in/1.out`、`2.in/2.out`、`3.in/3.out`（无大/小样例子目录、无 readme）。
  样例 1、2 取 `sample/`；样例 3 为大样例（默认 `data/6`，满足测试点 6~8）。
- **OJ 题面引用**：

```markdown
## 样例 3

（见题目附件 [climb_samples.zip](file://climb_samples.zip)，其中样例 3 满足测试点 6, 7, 8 的约束。）
```

- **PDF 题面引用**（官方格式）：

```markdown
## 样例 3

见选手目录下的 climb/climb3.in 与 climb/climb3.ans。
该样例满足测试点 6, 7, 8 的约束条件。
```

- 打包时大样例 zip 放入题目的 `additional_file/`（Hydro 导入为附加文件，供选手下载，
  **不进入评测数据**）。
- 大样例由生成器产出（满足对应档约束），答案由 std 生成并核验。
- 样例解释 1 必须紧跟样例 1 输出之后。

## 6. 定稿自检

- [ ] 任务目标在题目描述段落即可读懂
- [ ] 每个变量首次出现处有范围；总体保证覆盖所有变量
- [ ] 数据范围 = 总体保证 + 测试点表格 + 特殊性质定义（自由分档）
- [ ] 样例 1-2 内联且覆盖不同分支；完整样例 zip 平铺 1/2/3 并提供；样例解释 1 紧跟样例 1 输出
- [ ] 无任何做法提示；【说明与澄清】仅解释概念
- [ ] 只凭题面能写出正解（不自证则找盲审）；PDF 整卷无链接红框（hidelinks）
