# 知识点锁定流程（内部工作流）

> 本文件为内部出题参考，不代表任何官方标准。

## 目的

OI 出题需要做到“知识点可控”：题目考察什么、难度多高、用哪些算法，应在出题前明确，
避免超纲或为了难而难。本工作台将这一过程流程化。

## 锁定流程

1. **定级别**：入门级 / 提高级 / 专家级。
2. **选主知识点**：1 个，作为题目的核心算法，并记录难度系数【X】。
3. **选辅助知识点**：不超过 3 个，例如前缀和、字符串哈希、贪心等。
4. **校验**：对照对应速查表，确认所有知识点不超目标级别，难度系数不超过上限
   （入门级 ≤【5】、提高级 ≤【8】、专家级 ≤【10】且【10】仅限最高级别）。
5. **写题卡**：在母题卡 `templates/variation.md` 的 `knowledge_points` 中记录：
   级别 / 难度系数 / 主知识点 / 辅助知识点 / 超纲检查结论。
6. **锁定后不漂移**：题解、数据分档不得引入清单外算法；部分分靠特殊性质实现。

## 用户层知识库合并

- 先并入用户层：`~/.dsh-oi-workbench/kb/<level>/<topic>.md`（直接维护卡片文件），
  同名 `topic` 以用户卡为准；用户可自定义新层级。
- 再读内置速查表（`level-1-basic.md` / `level-2-intermediate.md` / `level-3-expert.md`）。
- 超纲检查仍以目标级别上限为准（用户卡不得放开上限）。
- 规范见 `specs/user-content.md`。

## 与分数表的关系

- 难度系数用于指导测试点分档：低难度知识点多放送分档，高难度知识点多放压轴档。
- 分档变化只改变数据规模与特殊性质，不应改变正解的知识点组合。

## 难度档位参考

| 档位 | 常见位置 | 期望通过率 | 测试点建议 |
|---|---|---|---|
| 送分题 | 入门组第 1 题 | 较高 | 15-20 点，多数小数据 |
| 基础题 | 入门组第 2 题 | 中等 | 20 点，2 档 |
| 中档题 | 入门组第 3 题 / 提高组第 1-2 题 | 较低 | 20-25 点，2-3 档 + 特殊性质 |
| 难题 | 提高组第 3-4 题 | 很低 | 25 点，3 档 + 2 个特殊性质 |
| 压轴题 | 提高组第 4 题 / 专家级 | 极低 | 25 点，复杂特殊性质组合 |

## 反超纲自检

- [ ] 正解只使用目标级别速查表内知识点
- [ ] 难度系数不超上限
- [ ] 特殊性质不引入清单外知识点作为通过手段
- [ ] 题解中不出现目标级别外的算法名词
- [ ] 数据分档能区分不同实现
